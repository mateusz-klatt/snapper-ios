# Contributing to Snapper iOS

Thanks for your interest. This is a single-maintainer project but PRs and issues are welcome.

## Quick workflow

1. Fork the repo
2. Create a topic branch off `master`
3. Make your change. Keep it focused — one concern per PR
4. Run `make check-all` locally — it must be green
5. Open a PR against `master`. Describe what changed and why

## Local setup

Prerequisites: **macOS with Xcode 26.2** (matches the iOS 26.2 SDK) and **XcodeGen** (`brew install xcodegen`).

```bash
make setup     # xcodegen generate -> Snapper.xcodeproj
make build     # iPhone 17 Pro simulator
make test      # XCTest + Swift Testing
```

By default the app talks to `http://localhost:8000`; pair with the upstream Snapper backend's `make dev-backend` in a separate shell. For features that exercise live WebSocket frames, run a real backend; most UI changes can be tested against fixtures via the existing test suite.

## Code style

- Swift 6.0 strict concurrency — use `@MainActor`, actors, and `Sendable` deliberately
- Prefer existing patterns (look at neighbouring services / views)
- No `// MARK: -` style comments in new code; doc comments use `///` triple-slash
- Tests live in `SnapperTests/` mirroring the source tree

## Testing

- `make test` — XCTest + Swift Testing
- `make coverage` — Xcode coverage → SonarCloud-compatible generic XML
- New features should land with tests covering the happy path and at least one edge case

## What lands fast

- Bug fixes with a regression test
- Accessibility improvements (VoiceOver, Dynamic Type, contrast)
- Concurrency tightening (closing actor reentrancy gaps)
- WebSocket / network resilience improvements

## What needs discussion first (open an issue)

- New top-level features
- Major refactors
- Dependency additions (the project intentionally has zero SPM dependencies)
- Breaking changes to the generated API surface (those are owned by the upstream backend's regeneration flow)

## Generated code

Files under `Snapper/Models/Generated/` are snapshots regenerated by the upstream Snapper backend. **Do not edit them by hand in a PR** — the change will be lost on the next regeneration. If you spot a problem, open an issue describing the schema-side fix instead.
